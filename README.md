# CanUSB — CAN / CAN-FD 总线分析仪

一款面向 **SLCAN 协议 USB-CAN 适配器**的 Windows 桌面上位机。用一条 USB 线把 CANable 之类的适配器接到电脑，就能实时看总线报文、画趋势曲线、发报文、做协议诊断。

界面采用全圆角工业 HMI 风格，同一窗口内分六个功能页，无需切换工具。

---

## 支持的硬件

| 适配器 | 芯片/固件 | 通信协议 | 说明 |
|---|---|---|---|
| **CANable 1.0** | candleLight + slcan | SLCAN（`t/T/r/R`） | VID:PID `16D0:117E`，最常见组合 |
| **CANable 2.0** | CANable2 固件 | SLCAN + CAN FD（`b/B`） | 实测固件 `16e7497`，支持 FD 变长数据 |
| **USB2CANFDV1** | 增强 slcan | SLCAN + CAN FD | 支持 `Y` 指令查询/切换 CAN FD 模式 |
| **WeAct Studio USB2CAN** | 定制 slcan | SLCAN + CAN FD | VID:PID `0483:5740`，串口序列号以 `AAA` 开头 |
| **candleLight / gs_usb 系** | 需刷 SLCAN 固件 | SLCAN | 刷写 slcan 或 candleLight2slcan 后可用 |

串口侧固定 **1 Mbaud**（USB-CDC 虚拟串口下不影响实际带宽），CAN 侧波特率可选：

- **标称波特率**：10k / 20k / 50k / 100k / 125k / 250k / 500k / 800k / 1M（对应 SLCAN `S0`~`S8`）
- **CAN FD 数据波特率**：1M / 2M / 4M / 5M（对应 `Y1`~`Y4`）

## 功能

### 1. 报文追踪

总线所有报文的实时列表，列为 `时间戳 / 间隔 / CAN ID / 格式 / DLC / 数据(Hex)`。

- **间隔列**：显示与上一帧的时间差（`+388.6 ms`、`+1.19 s`），不用心算周期
- **ID 过滤**：输入框填 `123,0x456` 之类，多个 ID 用逗号/空格分隔，表格只留匹配行，右下实时显示 `过滤 2 个 ID · 40 帧`
- **清空报文**：一键清表并同步清零统计

### 2. 接收曲线

选一个 CAN ID 和一个数据源（字节 0~7、全部字节和、DLC），把该字段的数值画成实时折线。

- 240 点滚动窗口，Y 轴自适应并留 18% 余量
- 2px 折线 + 竖向渐变填充，末端圆点标出当前值
- 支持暂停（保留曲线）与清空

### 3. 发送帧

单帧发送与批量发送共用一套字节网格输入（表头标注 0-7），与报文表格同一视觉语言。

- **单帧**：填 CAN ID、选帧类型（自动识别/标准/扩展）、勾 BRS、按字节填数据
- **批量**：5 行输入，每行一条 `ID + 字节`，行间隔 0~100 ms 可调，空行自动跳过
- **键盘流**：`Enter` / `→` 跳到下一个字节，`←` 回退，不用鼠标
- 帧类型与 BRS 由上方单帧卡片统一控制

### 4. 统计

按 **方向 + CAN ID** 聚合总线收发情况，四张指标卡 + 一张明细表。

- 指标卡：实时帧率、收发总数、链路状态、错误寄存器（各自独立配色）
- 明细表：方向（RX 绿 / TX 琥珀）、帧数、占比、**平均周期**、DLC、最近数据
- 表按帧数降序，每 500ms 刷新一次

### 5. 诊断

直接和适配器对话，排查"为什么连上了却没数据"这类问题。

- 输入任意 SLCAN 命令（`V` 版本、`E` 错误寄存器、`F` 状态标志、`Z0` 开通道、`C` 关通道），回车即发
- 三个快捷按钮一键执行 V / E / F
- 通信日志带毫秒时间戳：`>>` 是发出的命令，`<<` 是设备回显与驱动消息，连接过程也会自动留痕

### 6. 适配器信息

列出支持的硬件、串口参数、固件版本与链路自检结果。

## 实现

### 通信层

SLCAN 是纯 ASCII 行协议，一行一条报文，`\r` 结尾：

```
t1238AABBCCDDEEFF     标准帧 ID=0x123 DLC=8
T18DAF1108...         扩展帧 29 位 ID
r1234                 远程帧
b1239...              CAN FD，首字符后紧跟 DLC 码
```

`SlcanDriver` 把串口读写封装成事件：`FrameReceived`（收到报文）、`LogMessage`（回显与告警）。连接时依次握手：先发 `C` 关闭通道 → `S6` 设波特率 → `O` 开通道 → `V` 读版本 → `E` 读错误寄存器，任一步无回应就抛 `[Warn]`，避免"显示已连接但收不到帧"。

非报文回显（如 `V1013`）不再丢弃，而是走 `LogMessage` 通道给诊断页，这样固件版本、错误寄存器都能看到原始值。

### 接收链路

```
串口线程 ReadLine
   → ConcurrentQueue<CanFrame>        （无锁队列入队）
   → 30ms UI 定时器批量出队             （一次取走多帧，减少重绘次数）
   → _displayBuffer / _viewFrames     （原始缓冲 + 过滤后视图）
   → VirtualMode DataGridView        （只按需渲染可视行）
```

三个消费者共享同一份帧数据：报文表格、统计聚合、曲线采样，互不干扰。

### 线程模型

- 串口线程只做解析与入队，不碰任何 UI 控件
- UI 定时器（30ms）负责取数据、刷表格、刷状态栏
- 统计用 `Dictionary + lock`，驱动线程写、UI 线程每 500ms 取快照
- 曲线采样同样加锁，UI 线程按 60ms 独立重绘图表

### 界面绘制

WinForms 原生控件是直角的，全圆角外观由六个自绘控件实现：

| 控件 | 作用 |
|---|---|
| `RoundedCardPanel` | 圆角卡片容器，带 1px 描边 |
| `ModernButton` | 圆角按钮，悬停/按下渐变，支持彩色主按钮 |
| `ModernTextBox` | 圆角输入框，内部嵌无边框 `TextBox` |
| `FieldBox` | 下拉框圆角外壳，自动跟随内部 `ComboBox` 焦点 |
| `ByteGridInput` / `FrameGridInput` | 表格式字节输入，表头 0-7 |
| `LineChartPanel` | 自适应坐标轴的折线图 |

窗口圆角通过 DWM 的 `DWMWA_WINDOW_CORNER_PREFERENCE` 交给系统绘制，标题栏同步改为白色与顶栏无缝衔接。

## 解决的问题

开发和使用过程中踩到并修掉的具体问题：

**高频报文卡死**
原先每来一帧就 `Rows.Add` 一次，5000 fps 时 UI 线程被重绘占满。改为 `ConcurrentQueue` + 30ms 批量出队 + `VirtualMode` 表格，只渲染可视行，帧率上千也不卡。

**发送失败没有任何提示**
`SendFrame` 返回 `false` 时原来静默丢弃，用户以为发出去了。现在三层反馈：状态栏 4 秒提示、失败弹窗（附可能原因）、驱动层 `[TX Error]` 日志也接进状态栏。

**批量发送一行写错整批中断**
改为先整体解析再逐条发送，单行格式错误只跳过该行并在提示里说明"第 N 行第 M 字节不是合法 Hex"，其余照发；结束时汇总"3 条中 2 条失败"。

**连上了但收不到数据，无从排查**
新增诊断页，可直接下发 `V`/`E`/`F` 并看到原始回显，同时把连接握手过程（固件版本、链路自检）写进日志。

**圆角边框"被遮挡"**
三个层层叠加的坑：① 窗口 Region 比绘制路径小 1px，描边外半像素被裁；② 子控件是矩形，把父控件四角的圆角弧线整段盖住；③ 抗锯齿把 1.5px 线摊到 2~3 个像素上，颜色从 `#6B7280` 淡化成 `#C8CCD2`。分别用 Region 与绘制路径对齐、给子控件设同半径圆角 Region、描边单独关闭抗锯齿解决。

**125% 缩放屏上线条发虚**
半像素坐标在非整数缩放下无法对齐物理像素。改为描边中心线内缩半个线宽（1.5px → 0.75），并让子控件尺寸按 `PreferredSize` 反推，保证底边描边不被下拉框压住。

**下拉框聚焦时没有边框反馈**
`FieldBox` 的 `IsFocused` 从未被赋值，导致下拉框无论怎么点都不变蓝。改为容器监听内部控件 `GotFocus/LostFocus`，与输入框行为统一。

**相邻帧间隔要靠肉眼比对时间戳**
表格新增「间隔」列，直接算相邻帧时间差，秒级自动切换单位。

## 常见问题

**下拉框里找不到串口**
检查数据线（部分线只能供电不能传数据）与驱动。设备管理器里应出现 `USB 串行设备 (COMx)`。点顶栏 `⟳` 可重新扫描。

**提示"已连接"但报文表没有数据**
先确认总线两端 120Ω 终端电阻都在、波特率与对端一致；再打开「诊断」页发 `V` 看是否有回显，有回显说明串口通、问题在 CAN 侧。

**收不到 CAN FD 报文**
适配器固件需支持 FD；在顶栏勾选 `CAN FD` 并选择数据波特率，同时确认对端使用的 FD 参数一致。

**报文间隔忽大忽小**
USB-CDC 批量传输会带来毫秒级抖动，`间隔` 列反映的是**软件收到报文的时间**，不是总线上的精确时刻。需要精确时序请用示波器或带硬件时间戳的适配器。
